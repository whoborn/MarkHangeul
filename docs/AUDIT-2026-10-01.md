# MarkHangeul 전체 코드 점검·수정 보고서

작성일: 2026-10-01 (Asia/Seoul)

## 1. 최종 판정

기존 구현은 파서와 정적 배포 골격을 갖췄지만, **한 음절의 글자 자체로 4·6·8성 차이를 드러내는 목표에는 부족했습니다.** 단음절의 시작 높이만 반영하고 몇 가지 회전 형태로 묶는 방식, 실제 배치 폭과 다른 장평, 언어별 번호의 임의 fallback, Markdown 원문 HTML 실행 경로를 수정했습니다.

수정 후 중국어 4성·광둥어 6성·시연용 8개 contour는 보조선 없이 서로 다른 글자 변형을 생성합니다. 사용자 contour는 음절 내부와 여러 글자 범위 모두에 적용됩니다. Markdown 보호·원문 보존·파일 내보내기·하위 경로 정적 빌드를 함께 보완했습니다.

그러나 **세계 모든 언어의 발음을 한글 높낮이와 장평만으로 완전·유일하게 표현했다는 판정은 하지 않습니다.** 음소와 발성 방식, 성조 변조, 방언 차이, 사람의 식별률은 별도 문제입니다. 이번 수정은 범용 입력과 시각화 기반을 구현한 것이며, 전 세계 언어의 발음 규칙 사전을 완성한 것은 아닙니다.

## 2. 분석 범위와 구조

원본 기획 `plan_MarkHangeul_v1.3.md`, `v1.4.md`, Rust core/web 전체 소스 및 테스트, CSS, Trunk/HTML 진입점, Cargo 의존성, GitHub Actions, React 프로토타입의 파서·타입·렌더러·UI·테스트·설정, 기존 README/문법을 검토했습니다. 생성된 의존성·빌드 산출물은 애플리케이션 소스 검토 대상에서 제외했습니다.

| 계층 | 기존 상태 | 판단·수정 |
| --- | --- | --- |
| Rust core | AST·파서·serializer 분리 | 유지. 성조 해석·유효성 검사를 core로 이동 |
| core render_model | CSS class만 제공, web에서 같은 매핑 재작성 | web이 core class 매핑을 재사용 |
| web preview | Markdown·HTML·성조 사전·glyph 처리 혼합 | 성조 의미 해석은 core, 안전한 Markdown/SVG 조판은 web으로 분리 |
| AST | 작은 Text에도 큰 annotation variant 크기가 적용 | annotation을 Box로 간접화. JSON 구조 유지, Rust 생성 API 변경 |
| Markdown 보호 | fence·backtick·달러 문법 자체 구현 | pulldown-cmark source offset으로 일반 텍스트만 허용 |
| React | 4성 제한, Markdown 렌더링/보호 없음, Rust와 타입도 다름 | 보존용임을 UI·README에 명시. 기준 구현/배포에서 제외 |
| 빌드·배포 | 저장소 이름 경로 고정, PR 검증 없음 | Pages base_path 사용, 별도 CI 추가, Trunk 버전 고정 |

초기 기획의 “core / UI / 정적 배포” 3계층은 적절합니다. 두 언어 구현을 동시에 최신 기준으로 유지하는 것은 문법 분기를 만들므로 Rust/WASM을 유일한 기준 구현으로 정했습니다. React를 최신 6·8성 앱으로 오해하지 않도록 표시했습니다.

## 4. 성조·장평의 의미와 구현

### 성조 해석

우선순위는 `toneContour` → `toneSystem` → `lang` → 기본 중국어입니다. 명시한 toneSystem이 lang보다 우선합니다.

| 체계 | 교육용 기본 contour |
| --- | --- |
| 중국어 4성 | 55 / 35 / 214 / 51 |
| 광둥어 6성 | 55 / 35 / 33 / 21 / 13 / 22 |
| generic-8 시연 | 55 / 35 / 214 / 51 / 33 / 22 / 53 / 24 |

광둥어 2·5성은 기존 25·23 고정값에서 [Jyutping 공식 표](https://jyutping.org/en/jyutping/)에 제시된 35·13을 대표값으로 사용하도록 정리했습니다. 발화 변이를 모두 포괄한다는 뜻은 아니며, 사용자가 contour를 덮어쓸 수 있습니다.

실제 8성 언어는 단순히 음높이 8개를 임의로 번호 붙여서는 안 됩니다. `generic-8`은 렌더링 대조용이며, 실제 자료는 `lang`, `tone`, `toneContour`, `duration`, `ipa`, `note`를 함께 기록합니다. 동일한 contour라도 음소·음절 종결·발성 방식이 다르면 같은 발음이 아닙니다.

### 글자 변화

contour의 지점 간 선형 보간을 통해 한 glyph당 16개 세로 영역을 이동합니다. 1~5단계는 글자 높이에 비례해 이동하므로 글자 크기를 바꿔도 상대적인 표현을 유지합니다. 여러 grapheme 범위는 전체 범위에 걸쳐 contour가 진행하며 글자마다 같은 곡선을 반복하지 않습니다.

장단은 0.72 / 0.84 / 0.93 / 1 / 1.08 / 1.20 / 1.42배이며 같은 값이 실제 SVG 배치 폭에 반영됩니다. 높낮이와 길이를 혼동시키지 않도록 성조 번호 자체로 장평을 임의 변경하지 않습니다. 강세는 높이, Markdown 굵기는 원문 의미를 유지합니다.

## 5. Markdown 호환성 판정

| 맥락 | 처리 |
| --- | --- |
| 본문·제목·강조·취소선·목록·표·링크 표시 문구 | annotation 렌더링 지원 |
| 인라인/블록 코드·수식 | 원문 보존 |
| 링크 목적지·참조 정의·이미지 설명 | 원문 보존, annotation 비처리 |
| 원시 HTML | 실행하지 않고 텍스트로 표시 |
| 외부 Markdown 뷰어 | `.mh.md` 원문으로 읽기 가능, 자동 글자 변형 없음 |
| 일반 MD export | 정상 annotation을 제거한 Markdown. 오류는 원문 유지 |
| 독립 HTML export | CSS/SVG 포함, 발음 표시 보존. 수식은 TeX 원문 |

Markdown event offset 활용은 [pulldown-cmark의 공식 API](https://docs.rs/pulldown-cmark/latest/pulldown_cmark/struct.OffsetIter.html)에 기반합니다. 범위 안에 Markdown 구조를 중첩하는 문법과 중첩 범위는 지원하지 않습니다. 일반 중괄호와 확장 문법의 충돌은 `\{` 또는 코드 표기로 피합니다.

모든 Markdown dialect의 완전 적합성을 주장하지 않습니다. 특히 GitHub는 임의 CSS·SVG·스크립트를 그대로 허용하는 호스트가 아니므로, 시각 표현 공유의 기준 산출물은 독립 HTML입니다.

## 6. 배포 형태

- Rust/WASM/Yew를 Trunk로 빌드하여 `dist/` 전체를 HTTP(S) 정적 서버에 배포합니다.
- 서버 API·계정·데이터베이스 없이 편집과 발음 렌더링이 가능합니다.
- `.wasm` MIME은 `application/wasm`, public URL은 실제 호스팅 경로와 일치해야 합니다.
- `deploy-pages.yml`: main push/수동 실행, 테스트, Pages metadata, 하위 경로 반영, artifact와 deploy.
- `ci.yml`: PR/push에서 fmt, test, Clippy, WASM target check, `/MarkHangeul/` release build.
- Trunk 0.21.14와 Cargo.lock 사용. MathJax 3.2.2 CDN 버전 고정.
- MathJax의 [ui/safe](https://docs.mathjax.org/en/v3.2/options/safe.html)를 사용해 수식 내부 URL·사용자 class/id/style을 차단합니다.
- MathJax는 온라인 수식 조판에만 필요합니다. CDN 장애가 발음 표시를 막지 않도록 했습니다.
- 실제 GitHub Pages 게시/원격 저장소 설정 변경은 이번 작업에서 수행하지 않았습니다.

Pages metadata 기반 경로는 [configure-pages 공식 action 정의](https://github.com/actions/configure-pages/blob/main/action.yml), 정적 산출물 배포 흐름은 [GitHub 공식 문서](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), public URL 반영은 [Trunk 공식 안내](https://trunk-rs.github.io/trunk/guide/advanced/paths.html)를 따릅니다.

## 7. 검증

- Rust: core 21개 + web 12개 = 33개 테스트.
- 4·6·8개 profile의 고유성 및 **보조선을 숨긴 실제 glyph transform**의 고유성 회귀 검사.
- contour 단독 입력, 분해형 자모, 따옴표 값, 잘못된 boolean/체계/contour, 오류 export 보존 검사.
- Markdown 보호, HTML/URL 공격 입력, 원문 강조·코드·링크·표, standalone HTML 회귀 검사.
- cargo fmt, strict Clippy, wasm32 target check 및 `/MarkHangeul/` release build.
- 구 React: Vitest 8개 및 TypeScript/Vite build. 구형 명세 테스트임에 유의.
- 실제 Chromium: 하위 경로에서 WASM 로드, 성조 표 3개, 오류 0, 장평 width 비례, Enter 선택, Markdown 유지, script 비실행, javascript URL 제거, HTML 다운로드.
- standalone HTML을 file://로 열어 glyph 조판과 스크립트 없음 확인. MathJax 수식 2개 조판 및 28px 크기 조절 확인.
- 모바일 390px: 문서 전체 가로 넘침 검사와 실제 성조 표 스크린샷 확인.
- 브라우저 결과물은 로컬 `output/playwright/`에 보관하며 Git에서 제외합니다.

자동 geometry 고유성 검사는 “사람이 100% 쉽게 구분한다”는 실험 결과가 아닙니다. 사용자 실험은 수행하지 않았습니다. 브라우저 검증 범위는 Chromium이며 Safari·Firefox 및 다양한 한글 폰트의 별도 검증은 남아 있습니다.

## 8. 남은 한계와 후속 목표

1. **언어별 정확성**: 검증된 언어·방언별 성조 사전, 문맥 변조, 경성, 입성·발성 방식 모델이 필요합니다. 현재 미지원 언어에는 임의 값을 제공하지 않습니다.
2. **음소 표현**: 현대 한글에 없는 소리, 유성/무성·기식·비음·모음 차이 등을 높낮이와 폭만으로 모두 구별할 수 없습니다. 현재 IPA/phoneme과 관련 boolean은 AST 메타데이터이며 시각 음소 변환을 하지 않습니다.
3. **인지 검증**: 4·6·8성의 번호를 숨긴 상태에서 언어 학습자에게 맞히게 하고 혼동 행렬·정답률·판독 시간을 측정해야 합니다. 작은 변화(예: 22↔33)와 시력·폰트·화면 크기 영향을 별도로 점검해야 합니다.
4. **조판 품질**: SVG strip은 연속 곡면 변형의 근사입니다. 라틴 자폭은 근삿값이고 복잡한 문자권의 연결형 조판을 보장하지 않습니다. 한글 가변 폰트/윤곽 기반 변형은 향후 개선입니다.
5. **문서 편집 UX**: 자동 저장·파일 가져오기·실시간 협업은 없습니다. 원문 파일 저장 후 붙여넣기로 재사용합니다. 대용량 문서의 성능 한계도 별도 부하 시험이 필요합니다.
6. **공유·유통**: 외부 Markdown 도구용 정식 플러그인은 없습니다. 소스/Plain/HTML/JSON 경로가 현재의 명시적 호환 계약입니다.

| Markdown·웹 배포 | 보호 범위·안전한 렌더링·4종 파일 export·Pages 경로·CI 수정 및 로컬 검증 |
| 전체 개발 목표 | 범용 표현 엔진 기반은 개선 완료. 모든 언어의 음운 체계 완성·인지적 검증은 별도 단계 |


## 10. 후속 보정: 연결성과 시인성

사용자 화면 피드백에 따라 위 보고서의 16영역 렌더링을 다음 방식으로 대체했습니다. 이 절이 이전 조판 설명보다 우선합니다.

- 16개의 얇은 조각을 서로 다른 높이로 이동하던 방식 제거. 평탄·상승·하강은 glyph 전체를 한 번 렌더링하고, 굴곡만 실제 contour의 꺾임에서 분할합니다. 접합점의 위치가 일치하는 연속 affine 변환으로 획의 계단과 중첩을 줄였습니다.
- 음높이 한 단계 이동량 0.14em → 0.06em. 최대 인접 고저 차이 0.56em → 0.24em으로 축소하면서 성조별 geometry 고유성을 유지합니다.
- inline-flex의 합성 기준선·음수 margin을 없애고 SVG baseline을 일반 본문 baseline과 정렬합니다. 명시 범위의 좌우 padding도 제거합니다.
- 본문 행간 2.4~2.6 → 1.85. 보조선 높이 0.78em → 0.35em. 보조선은 글자보다 작고 가볍게 표현합니다.
- 큰 성량의 중복 text-shadow 제거. 좁은 라틴 글자를 강제로 넓히던 textLength도 제거하고 글자별 자간을 사용합니다. Latin 자간은 여전히 폰트별 실측이 아닌 근사값입니다.
- 강세·성량의 세로 확대는 글자 아래 기준선을 중심으로 하여 단어 흐름을 보존합니다.
- 4·6·8성의 보조선 없는 구별 회귀 검사를 유지하고, 곡선 접합 연속성·이동 상한·불필요한 분할 방지 검사를 추가했습니다.
- 후속 검증: Rust 35개 테스트, Clippy, WASM 빌드 및 데스크톱/390px 모바일의 연결된 문장·혼합 강조·장단·상하 교차 표시 검사.

새 조판은 음높이를 표시하는 시각적 배율을 줄인 것이며 저장된 발음 contour나 장단 값은 변경하지 않습니다. 결과 이미지는 `output/playwright/typography-desktop.png`, `typography-mobile.png`에서 확인할 수 있습니다.


## 11. 후속 확장: 언어·지역별 6성·8범주

조판 보정까지의 상태를 `bd24640`으로 먼저 커밋한 뒤 별도로 확장했습니다.

- 성조 사전을 `render_model/tone_systems.rs`로 통합하고 UI·예제·검증이 같은 정의를 사용합니다.
- 광둥어 6성, 하노이 베트남어 6범주와 입성 2범주를 포함한 분석, 표준 태국어 5성을 제공합니다. 실제 언어와 generic-8 시연을 구분합니다.
- `phonation`과 `checked`를 정식 AST 속성으로 추가하고 보조선·Inspector·HTML export에 연결했습니다. 글자 획은 추가로 흐리거나 변형하지 않습니다.
- 국가 하나에 모든 방언을 묶지 않고 지역을 표시합니다. 하노이는 이름/역사 코드로 입력하며 임의의 tone=7/8 순서를 만들지 않습니다.
- 비교 예제로 바꾸기 UI 및 근거 자료 링크를 추가했습니다. 하노이 contour는 자료의 기술을 1~5 척도로 단순화한 교육용 근사이며 자동 음성 전사가 아닙니다.
- 등록된 범주 전체의 contour+발성+입성 조합, 잘못된 값, 입성 범주 충돌, 명시 override, JSON 보존, 예제 문서와 화면 표시를 회귀 검사합니다.

정확한 문법·프로필·근거·한계는 [언어·지역별 프로필](LANGUAGE-PROFILES.md)을 참조하세요. 이 절이 앞의 ‘태국어 미지원’ 및 ‘실제 8범주 미지원’ 상태 설명보다 우선합니다.

## 12. 유럽권·아랍권 및 세계 언어 예제 확장

기존 선택기는 성조 체계 중심으로, 비성조 언어의 어휘 강세·장단·원어 문자를 비교하는 경로가 없었습니다. 성조 레지스트리에 유럽 언어를 억지로 넣지 않고 별도 예제 레지스트리와 표기 방식 선택기를 추가했습니다.

- 11개 언어, 12개 지역/발음 프로필. 영어는 미국과 영국을 분리합니다.
- 원어+한글 / 한글 / 원어의 3가지 Markdown 생성 방식. IPA·뜻·언어/지역·출처를 유지합니다.
- 아랍 원문은 결합 문자를 보존하는 일반 텍스트로 표시하고 선택기에서는 방향을 격리합니다.
- 범위형 주석을 사용해 한 원어 음절에 대응하는 여러 한글 글자에 속성을 함께 적용합니다.
- 비음화·연자음화 등의 기존 메타데이터가 실제 음소 모양으로 자동 변환되지 않는 점을 화면과 문서에 명시했습니다.

검증: 36개 언어/표기 조합의 파싱, 원어 열 선택, IPA/언어 메타데이터, plain Markdown·HTML 보존을 회귀 검사합니다. 기존 4·6·8성 테스트와 함께 수행합니다. 웹 배포는 기존 정적 WASM 구조이며 추가 서버·API 키·음성 서비스가 필요하지 않습니다.

최종 확인: Rust 테스트 43개 통과, 포맷·Clippy·WASM 대상 검사 통과, `/MarkHangeul/` 하위 경로 release 빌드 성공. 실제 브라우저 36개 조합과 아랍어 방향/문자 보존, HTML 및 390px 모바일 가로 넘침 검사를 통과했습니다. 원격 게시 작업은 수행하지 않았습니다.
